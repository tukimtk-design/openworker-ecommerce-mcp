แม่แบบที่ 1: สั่งพัฒนาฟีเจอร์ / Tool ใหม่ตามกฎ ZERO-DEFECT
--------------------------------------------------------------------------------
[คัดลอกข้อความด้านล่างนี้ส่งให้ Jules]

สวัสดี Jules! ในฐานะ AI Developer Agent ของโปรเจกต์ openworker-ecommerce-mcp
ฉัน (AI Project Controller) ขอสั่งการให้คุณเริ่มพัฒนา Task ดังต่อไปนี้:

🎯 หัวข้องาน: [ระบุชื่อ Feature หรือ Task เช่น Phase 12 Option A: Predictive Inventory]
📁 ไฟล์ที่ต้องสร้าง/แก้ไข:
- [ระบุชื่อไฟล์ เช่น src/tools/predictive-inventory.ts]
- src/index.ts (ลงทะเบียน Tool ใหม่)

📋 ขอบเขตและฟังก์ชันที่ต้องทำ:
1. พัฒนาฟังก์ชัน [ระบุรายละเอียดฟังก์ชัน]
2. กำหนด Tool Name ให้ขึ้นต้นด้วย Prefix `ecommerce_*` เสมอ
3. ปฏิบัติตาม 🛑 ZERO-DEFECT PROTOCOL อย่างเคร่งครัด:
   - ฟิลด์ `type: "array"` ทุกตัว ต้องมี `items` กำกับชนิดข้อมูลเสมอ
   - ฟิลด์ `type: "object"` ทุกตัว ต้องมี `properties` และ `required` (หากเป็น Dynamic Object ให้ใส่ Dummy Property `_dummy`)
   - ห้ามใช้ Loose Schema หรือ `$schema` keywords
4. เขียน Unit Test สำหรับ Tool ใหม่ใน `src/tests/`

🧪 การตรวจสอบก่อนส่งมอบ:
- รัน `npm run build` (tsc) ต้องผ่าน 100% ไร้ Error
- รัน `npm test` หรือ Sanity Check ต้องผ่าน 100%
- ทำสรุปรายงานผลการพัฒนาพร้อมแนวทางการใช้งานมาให้ Controller ตรวจสอบ

เริ่มดำเนินการได้ทันทีครับ!

แม่แบบที่ 2: สั่งตรวจสอบและแก้ไข SCHEMA (SCHEMA AUDIT & FIX)
--------------------------------------------------------------------------------
[คัดลอกข้อความด้านล่างนี้ส่งให้ Jules]

สวัสดี Jules! มีคำสั่งด่วนจาก Controller ให้ดำเนินการตรวจสอบและแก้ไข Schema:

🎯 งาน: ตรวจสอบความเข้ากันได้กับ Google Vertex AI และ Anthropic Claude API
📋 สิ่งที่ต้องทำ:
1. ตรวจสอบไฟล์ `src/index.ts` และ Tools ทุกตัว
2. ตรวจสอบว่าไม่มีฟิลด์ `array` ใดที่ขาด `items` และไม่มีฟิลด์ `object` ใดที่ขาด `properties`
3. หากพบ Loose Schema ใน Tool ใด ให้ทำการ Refactor ทันทีตามมาตรฐาน Strict Typing Mandate ใน `AGENTS.md`
4. ทดสอบคอมไพล์ TypeScript ด้วย `npm run build` และรัน Unit Tests
5. ส่งรายงานสรุป Tool ที่ได้รับการแก้ไขทั้งหมดกลับมายัง Controller

ดำเนินการได้ทันทีครับ!
