1. กฎเหล็กการสร้าง SCHEMA (STRICT TYPING MANDATE)
--------------------------------------------------------------------------------
Google Vertex AI และ Claude มีตัวตรวจสอบ Function Calling Schema ที่เข้มงวดมาก หากพบ Loose Schema ระบบจะปฏิเสธการเชื่อมต่อทันที:

กฎข้อที่ 1: ห้ามสร้าง Array เปล่า (Mandatory Array Items)
- ทุกพารามิเตอร์ที่เป็น `"type": "array"` จะต้องระบุฟิลด์ `"items"` กำกับชนิดข้อมูลภายในเสมอ
- ตัวอย่างที่ถูกต้อง:
  ```json
  "targetPlatforms": {
    "type": "array",
    "items": { "type": "string" }
  }
  ```
- ตัวอย่างที่ผิด (ห้ามทำ):
  `"targetPlatforms": { "type": "array" }`  <-- ผิดทันที

กฎข้อที่ 2: ห้ามสร้าง Object ว่าง (Mandatory Object Properties)
- ทุกพารามิเตอร์ที่เป็น `"type": "object"` จะต้องมีฟิลด์ `"properties"` เสมอ
- หากเป็น Dynamic Object (ที่รับคีย์อะไรก็ได้) ให้ใช้เทคนิค Dummy Property ร่วมกับ `additionalProperties`:
  ```json
  "params": {
    "type": "object",
    "properties": {
      "_dummy": { "type": "string", "description": "dummy field for vertex ai compatibility" }
    },
    "additionalProperties": true
  }
  ```
- ตัวอย่างที่ผิด (ห้ามทำ):
  `"params": { "type": "object" }`  <-- ผิดทันที

กฎข้อที่ 3: ห้ามใช้ Unsupported Schema Keywords
- ห้ามใช้ `$schema`, `$ref`, `patternProperties` หรือ Nested `anyOf`/`oneOf` ที่ซับซ้อน

กฎข้อที่ 4: Strict Namespace Prefix
- ทุก Tool ใหม่ต้องขึ้นต้นด้วย Prefix `ecommerce_*` เท่านั้น
- ห้ามใช้ Prefix `browser_*`, `file_*`, `git_*`, `shell_*` หรือ `process_*` เพื่อไม่ให้ทับซ้อนกับ System Tools ของ Openworker

    - ดูว่ามี `type: "object"` ตัวไหนที่ลืมใส่ `properties` หรือไม่

[ ] Checklist 2: ตรวจสอบผลการคอมไพล์ TypeScript
